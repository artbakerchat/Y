Module 1 Foundation

The Agent Loop: Tools Give Reasoning Reach

Agents for Humans starts with a small, inspectable cycle: the model understands a request, selects a tool, receives its result, and keeps reasoning until it can respond.

1. Input & Context
The user prompt, palette, and session history enter the request.
2. Reason & Select
The model chooses whether it needs get_palette, search_palette, or suggest_related_words.
3. Execute & Return
A plain Python @tool function runs, its result returns to reasoning, and the loop ends with an answer.
# You write the tools; Strands runs the loop. agent = Agent(tools=build_tools(palette), system_prompt=SYSTEM_PROMPT) async for event in agent.stream_async(prompt): # tool result -> next reasoning cycle -> response yield event
Module 2 Control Layer

Hooks Make the Loop Accountable

The Agents for Humans track keeps model reasoning flexible while adding deterministic boundaries around it. A rate limiter resets per request and blocks a tool after three calls.

Before Invocation
RateLimiterHook.reset clears per-tool counts when a new user request enters the loop. Each turn gets a fresh budget.
Before Tool Call
check counts calls by tool and sets event.cancel_tool when the limit is exceeded. The model receives the reason and must adapt.
# The hook stays separate from tools and prompts. agent = Agent( tools=build_tools(palette), hooks=[RateLimiterHook(max_calls=3)], )
Module 3 Knowledge Layer

Skills Teach the Agent How to Work

Agents for Humans keeps workflow knowledge in focused skills/<name>/SKILL.md procedures. The agent sees skill descriptions first, then loads the relevant procedure on demand instead of carrying every workflow in its system prompt.

Conversation Style
Tone, voice, and rewrite requests. Preserves intent, uses search_palette when useful, and keeps revisions focused.
Palette Building
Theme and word-palette growth. Uses get_palette and suggest_related_words without claiming unconfirmed changes.
Word Exploration
Meaning, origin, connotation, and poetic use. Uses consult_word_specialist and separates facts from interpretation.
# Progressive disclosure: skills suggest; tools act. skills_plugin = AgentSkills(skills=["./skills"]) agent = Agent(plugins=[skills_plugin], tools=build_tools(palette))
Module 4 Memory Layer

Persistence and Context Are Different Jobs

Agents for Humans now separates durable session state from the context sent to the model. Native S3 sessions survive restarts, while a sliding window keeps each request bounded.

Session Manager
S3SessionManager uses the same session_id to restore conversation state across fresh Agent instances. Set FORGE_SESSION_BUCKET to enable it.
Conversation Manager
SlidingWindowConversationManager(window_size=20) limits what enters model context. Persistence keeps history; context management keeps requests practical.
# Same session ID: new agent, restored conversation. session_manager = S3SessionManager(session_id=session_id, bucket=bucket) agent = Agent( session_manager=session_manager, conversation_manager=SlidingWindowConversationManager(window_size=20), )
Module 5 Delivery Layer

From Local Agent to Managed Runtime

Agents for Humans keeps the agent code intact and adds one production boundary: BedrockAgentCoreApp receives the request, while AgentCore packages, hosts, observes, and scales the runtime.

1. Package
agentcore deploy builds from app/ForgeAgent/pyproject.toml and includes the bundled tools, hooks, skills, and entrypoint.
2. Host
The managed AgentCore Runtime invokes @app.entrypoint with a payload and context, without application servers to operate.
3. Observe
CloudWatch receives runtime logs and telemetry. Invoke with a 33+ character session ID to test restored context.
# Deployment path agentcore deploy agentcore invoke --session-id customer-1001-session-refund-000001 "Continue our conversation." # Runtime session storage FORGE_SESSION_BUCKET=forge-session FORGE_SESSION_PREFIX=forge-sessions/
Domain Shift & Dual Runtime

Architecture Overview

The codebase adapts the 7-layer agentic patterns from a generic workshop into a custom Word-Craft AI Workspace across two distinct execution tracks.

JavaScript Worker Track
Located in src/worker.js. Production-ready Cloudflare Worker with AWS Bedrock Converse API integration. Implements Modules 1–6 (Tools, Hooks, Skills, Session history, Steering, and Multi-Agent delegation).
Python AgentCore Track
Located in app/ForgeAgent/main.py. Deployed via AWS Bedrock AgentCore. Now implements the Module 1–3 foundation: palette tools, the Strands agent loop, rate limiting, and on-demand Markdown skills.

Current State

Specialists as Tools

Module 6 extends Agents for Humans with the agents-as-tools pattern: Forge remains the orchestrator, while a focused technical specialist handles device problems in an isolated loop.

Orchestrator Agent (Forge)
Receives user intent, manages session context, handles palette requests directly, and decides when technical expertise is required.
Sub-Agent (Word Specialist)
Dispatched through tech_support_specialist. Runs a silent nested loop with check_device_compatibility and run_device_diagnostic, then returns findings to Forge.

Module 7 Quality Layer

Make Agent Behavior Measurable

Agents for Humans now has offline contracts for the two questions that matter before shipping: is the response useful, and did the agent follow the intended tool trajectory?

Output Contract
score_output checks required facts and forbidden claims without a model call. Use it for fast local regression checks; add an LLM judge for nuance and tone.
Trajectory Contract
score_trajectory extracts ordered tool calls and verifies workflows such as lookup → order history → refund.
# Fast, repeatable checks before deployment PYTHONPATH=evals python3 -m unittest discover -s evals -p 'test_*.py'
