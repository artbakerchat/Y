Forge / Larboard is a full-stack AI chat workspace where users chat with an AI agent using a personal word palette. Architecture has 3 tiers: (1) Local Node.js server (server.mjs) — pure Node http, serves index.html/pinball.html/prompt.html/pricing.html/printer.html, API: GET/POST /api/state + POST /api/ask + GET /api/health, sessions in .data/sessions/<uuid>.json with 48h TTL, calls Bedrock via @aws-sdk/client-bedrock-runtime with Strands as preferred path, rate limits: 20 req/day, 52 words/req, 16 chars/word. (2) Cloudflare Worker (src/worker.js) — deployed to larboard.ca, worker: larboard, R2 bucket: larboard-assets, sessions in R2, manual AWS Sig V4 signing, two AI paths: Bedrock Converse or AgentCore (AGENTCORE_RUNTIME_ARN), hourly cron to purge sessions, MODEL_REQUESTS_ENABLED=false by default, Cloudflare rate limiter on legacy redirects. (3) AgentCore Runtime (app/ForgeAgent/main.py) — Python 3.12, bedrock-agentcore + strands-agents, deployed via AgentCore CLI, optional S3 palette persistence (FORGE_PALETTE_BUCKET) and DynamoDB history (FORGE_SESSION_TABLE), 48h TTL, streams via agent.stream_async(). Frontend: index.html is the main chat UI (no build needed for Node); site/ is a React+TypeScript+Vite build (App.tsx) compiled and uploaded to R2; other pages: prompt.html, pinball.html, pricing.html, printer.html. Deployment via GitHub Actions (.github/workflows/deploy.yml) on push to main: builds React site, uploads assets to R2 via wrangler, deploys Worker; requires CLOUDFLARE_API_TOKEN and CLOUDFLARE_ACCOUNT_ID secrets. Key config: .env.example (AWS_REGION=ca-central-1, BEDROCK_MODEL_ID=ca.amazon.nova-micro-v1:0), wrangler.jsonc (default model ca.amazon.nova-lite-v1:0), agentcore/agentcore.json (one runtime ForgeAgent, no memory/KB), agentcore/aws-targets.json (empty — account/region not set), app/ForgeAgent/iam-policy.json (wildcard S3+DynamoDB, needs scoping for prod). Notable: aws-targets.json is empty so AgentCore CLI won't work until account/region is added; iam-policy.json uses arn:aws:s3:::*/* and arn:aws:dynamodb:*:*:table/*; MODEL_REQUESTS_ENABLED defaults false; React site/ and static index.html serve the same UI via different paths; requirements.txt is minimal. Agent replication context: forge.md gives an agent a high-level description of the architecture and file roles, config values and env var names, and a summary of what each tier does — but is missing the actual source code, exact API contracts, session state schema, UI design and styling, Vite/TypeScript config, Wrangler config details, GitHub Actions workflow steps, and IAM policy JSON; an agent reading only forge.md could build something similar in concept but would be writing from scratch, making it a design brief rather than a replication spec.
